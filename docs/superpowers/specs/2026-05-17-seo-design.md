# Spec — SEO foundation

**Date:** 2026-05-17

## Background

The site has minimal SEO surface today: only `<title>`, `<html lang>`, charset and
viewport in every page's `<head>`. There is no `robots.txt`, no `sitemap.xml`, no
meta description, no Open Graph tags, no canonical URL, and no hreflang signalling.
The legacy site at `https://helios2.mi.parisdescartes.fr/~lerb/` carried
`<meta name="author">`, a hand-curated `<meta name="keywords">`, and a short
`<meta name="description">`, but no modern SEO infrastructure either — so the new
site is currently slightly behind the legacy one on basic crawler hints.

## Goals

1. Provide a meta description, author, canonical URL, Open Graph and Twitter card
   tags on every page.
2. Signal FR↔EN translation pairs to crawlers via `hreflang` (head-level + sitemap).
3. Generate `robots.txt` and `sitemap.xml` from the build so crawlers can discover
   every page.
4. Preserve the legacy site's keyword inventory as defaults, with a per-page override.
5. No new external dependencies beyond `@astrojs/sitemap` (official Astro integration).

## Non-goals

- JSON-LD / Person structured data (knowledge-panel enrichment) — deferred.
- Google Search Console / Bing Webmaster verification meta tags — operational,
  the owner adds them when registering each property.
- Per-page Open Graph image overrides — site-wide `og:image` is
  `/img/photoweb.jpg`.
- Performance optimizations (CLS, LCP, font subsetting) — separate concern.

## Architecture

### 1. Head meta tags — `BaseLayout.astro`

`BaseLayout` is rendered by every page, so adding meta tags there reaches the whole
site without per-page work.

**New props (both optional):**
- `description` — page-specific meta description.
- `keywords` — page-specific comma-separated keywords.

**Computed in the frontmatter script:**
- `fullTitle = ${title} — Brigitte Le Roux` (same form as today's `<title>`).
- `metaDescription = description || strings.site.description` (per-locale fallback).
- `metaKeywords = keywords || strings.site.keywords` (per-locale fallback).
- `canonical = new URL(Astro.url.pathname, Astro.site).href`.
- `slug` derived from `Astro.url.pathname` (same logic as the recent LanguagePicker
  fix — strip the locale prefix, strip trailing slash, default to `"home"` for the
  root URL of each locale).
- `frExists` / `enExists` via
  `import.meta.glob('../../content/pages/**/*.md', { eager: true })`.
- `frUrl = new URL(slug === 'home' ? '/' : '/' + slug + '/', Astro.site).href`.
- `enUrl = new URL(slug === 'home' ? '/en/' : '/en/' + slug + '/', Astro.site).href`.
- `ogImage = new URL('/img/photoweb.jpg', Astro.site).href`.

**Tags emitted in `<head>`:**

```html
<meta name="description" content={metaDescription} />
<meta name="keywords" content={metaKeywords} />
<meta name="author" content="Brigitte Le Roux" />
<link rel="canonical" href={canonical} />

{frExists && <link rel="alternate" hreflang="fr" href={frUrl} />}
{enExists && <link rel="alternate" hreflang="en" href={enUrl} />}
{frExists && <link rel="alternate" hreflang="x-default" href={frUrl} />}

<meta property="og:title" content={fullTitle} />
<meta property="og:description" content={metaDescription} />
<meta property="og:url" content={canonical} />
<meta property="og:type" content="website" />
<meta property="og:locale" content={locale === 'en' ? 'en_US' : 'fr_FR'} />
<meta property="og:image" content={ogImage} />
<meta property="og:site_name" content="Brigitte Le Roux" />

<meta name="twitter:card" content="summary_large_image" />
<meta name="twitter:title" content={fullTitle} />
<meta name="twitter:description" content={metaDescription} />
<meta name="twitter:image" content={ogImage} />
```

Twitter card tags reuse data we already compute for Open Graph — five lines, no
extra plumbing.

### 2. Sitemap — `@astrojs/sitemap` integration

Adds one strict-pinned dependency in `package.json` and an `integrations` block in
`astro.config.mjs`:

```js
import sitemap from '@astrojs/sitemap';

export default defineConfig({
  site: 'https://brigitte-le-roux.com',
  i18n: {
    defaultLocale: 'fr',
    locales: ['fr', 'en'],
    routing: { prefixDefaultLocale: false }
  },
  integrations: [
    sitemap({
      i18n: {
        defaultLocale: 'fr',
        locales: { fr: 'fr-FR', en: 'en-US' }
      }
    })
  ],
  server: { port: 4321 },
  build: { format: 'directory' }
});
```

The `i18n` block makes the sitemap emit `xhtml:link rel="alternate" hreflang="..."`
entries inside the sitemap for FR↔EN page pairs. For FR-only pages
(e.g. `/bureau/`) it lists just the URL without alternates — the same behaviour as
the head-level hreflang tags.

Build output in `dist/`:
- `sitemap-index.xml` — the index, references the chunks.
- `sitemap-0.xml` — one chunk holding our ~50 URLs.

### 3. robots.txt — Astro static endpoint

Generated by `src/pages/robots.txt.js`:

```js
export const GET = ({ site }) => {
  const sitemap = new URL('/sitemap-index.xml', site).href;
  return new Response(
    `User-agent: *
Allow: /

Sitemap: ${sitemap}
`,
    { headers: { 'Content-Type': 'text/plain' } }
  );
};
```

`site` is sourced from `astro.config.mjs`, so the sitemap URL stays in sync with the
deploy target — no hardcoded domain.

The endpoint runs at build time and emits `dist/robots.txt`, which then flows to S3
via `yarn deploy`.

### 4. Default values — `content/i18n/{fr,en}.json`

A new `site` block is added to each locale file. Defaults are seeded from the
legacy site's keyword inventory and rewritten as natural-language descriptions.

`content/i18n/fr.json`:

```json
{
  "site": {
    "description": "Site personnel de Brigitte Le Roux, chercheuse en analyse géométrique des données (MAP5, Université Paris Cité ; CEVIPOF/CNRS).",
    "keywords": "Brigitte Le Roux, analyse géométrique des données, analyse des correspondances multiples, ACM, AGD, statistique appliquée, MAP5, CEVIPOF, sociologie quantitative"
  }
}
```

`content/i18n/en.json`:

```json
{
  "site": {
    "description": "Personal academic site of Brigitte Le Roux, researcher in Geometric Data Analysis (MAP5, Université Paris Cité; CEVIPOF/CNRS).",
    "keywords": "Brigitte Le Roux, Geometric Data Analysis, Multiple Correspondence Analysis, MCA, GDA, applied statistics, MAP5, CEVIPOF, quantitative sociology, case studies"
  }
}
```

`<meta name="keywords">` is largely ignored by modern search engines (Google has
not used it for ranking since 2009; Bing follows the same line), but it preserves
the legacy site's keyword record at near-zero cost and may still be parsed by
academic / niche search tools.

### 5. Content schema — `src/content/config.mjs`

The page collection schema grows by one optional field:

```js
keywords: z.string().optional()
```

`description` is already optional in the existing schema and is reused directly.

## Files touched

- `src/layouts/BaseLayout.astro` — meta tag emission (main edits)
- `src/layouts/PageLayout.astro` — pass `description` and `keywords` through
- `src/pages/[...slug].astro` + `src/pages/en/[...slug].astro` — pass
  `entry.data.description` and `entry.data.keywords` into `PageLayout`
- `src/pages/robots.txt.js` — new endpoint
- `src/content/config.mjs` — add `keywords` to schema
- `content/i18n/fr.json` + `content/i18n/en.json` — add `site.description` and
  `site.keywords`
- `package.json` — add `@astrojs/sitemap` (strict-pinned)
- `astro.config.mjs` — register sitemap integration
- `CLAUDE.md` — short "SEO" subsection explaining the `description` / `keywords`
  frontmatter fields and the i18n fallback location, so future content edits know
  where to set these values

## Verification

After `yarn deploy`:

- `curl https://brigitte-le-roux.com/robots.txt` returns the expected text body
  with the sitemap URL.
- `curl https://brigitte-le-roux.com/sitemap-index.xml` returns a valid XML index
  pointing at `sitemap-0.xml`.
- `curl https://brigitte-le-roux.com/sitemap-0.xml` lists every FR + EN URL with
  `xhtml:link rel="alternate" hreflang="..."` entries for translated pairs.
- View-source on any page shows: `<meta name="description">`, `<meta name="keywords">`,
  `<link rel="canonical">`, three `<link rel="alternate" hreflang>` tags (one
  fewer on FR-only pages), and the full Open Graph + Twitter card block.
- `scripts/check-links.sh` continues to return zero broken links.

## Out of scope

- JSON-LD `Person` / `ScholarlyArticle` structured data.
- Google Search Console / Bing Webmaster verification meta tags.
- Per-page Open Graph image override.
- Image alt-text audit.
- Backlink strategy — purely external work.

## Open questions

- **Manual Search Console submission** — once the sitemap is live, submit
  `https://brigitte-le-roux.com/sitemap-index.xml` to Google Search Console (and
  optionally Bing Webmaster Tools) for faster initial indexing. Out of code scope.
- **Per-page keyword overrides** — should specific high-traffic pages (CIGDA,
  publications) carry narrower keyword sets via the new `keywords:` frontmatter
  field? Can be deferred and added incrementally without further design work.
